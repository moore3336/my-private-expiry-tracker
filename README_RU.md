# Личный трекер сроков годности

Это стартовый серверный проект с одним общим паролем владельца. Приложение не раздаётся как публичный статический сайт: сервер сначала проверяет сессию и только затем отдаёт HTML.

## Что защищено

- Страница приложения доступна только после входа.
- Пароль хранится на сервере только в виде bcrypt-хеша.
- Cookie сессии имеет флаги HttpOnly, SameSite=Strict и Secure в production.
- Есть ограничение частоты попыток входа.
- Файлы проекта и папка private/ не публикуются как статические ресурсы.

## Важные ограничения

1. HTML/CSS/JavaScript, отправленные браузеру после успешного входа, можно изучить через инструменты разработчика. Этот проект закрывает приложение от посторонних посетителей, но не делает клиентский код невидимым для авторизованного пользователя. Для сокрытия алгоритмов их нужно отдельно переносить на сервер.
2. Исходное приложение сохраняет список продуктов в localStorage. Это означает, что данные остаются в браузере и не синхронизируются между устройствами. Для облачного хранения нужна отдельная серверная база данных с привязкой к владельцу и резервным копированием.
3. Не размещайте .env, пароль, хеш и ключи сессии в публичном репозитории. Используйте только HTTPS-хостинг и секреты в панели хостинга.

## Локальный запуск для проверки

Требуется Node.js 20 или новее.

```bash
npm install
node scripts/make-password-hash.js "ВАШ_ДЛИННЫЙ_УНИКАЛЬНЫЙ_ПАРОЛЬ"
```

Скопируйте полученный хеш в PASSWORD_HASH в переменных окружения. Создайте два длинных случайных секрета для SESSION_KEYS, например с помощью менеджера паролей. Не используйте примерные значения из документации.

Linux/macOS:

```bash
export PASSWORD_HASH='полученный_bcrypt_хеш'
export SESSION_KEYS='случайный_секрет_1,случайный_секрет_2'
npm start
```

Откройте http://localhost:3000. Для production обязательно включите NODE_ENV=production и используйте хостинг с HTTPS.

## Размещение в интернете

1. Создайте приватный репозиторий в GitHub/GitLab и загрузите туда содержимое архива.
2. Создайте Web Service на хостинге Node.js (например, Render или Railway) из приватного репозитория.
3. Команда сборки: npm install; команда запуска: npm start.
4. В панели хостинга задайте NODE_ENV=production, PASSWORD_HASH и SESSION_KEYS как секретные переменные окружения.
5. Включите HTTPS и не публикуйте репозиторий. Сам адрес сайта не является секретом — защиту обеспечивает вход по паролю.

## Выход

В этой минимальной версии выход из аккаунта выполняется POST-запросом /logout.
